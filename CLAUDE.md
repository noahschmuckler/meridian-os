### Track 2 — glossary / acronym mechanic 2026-05-04

Second track of the QOL roadmap. Builds directly on Track 1's cross-cutting bridges (`data-bubble-id`, `meridian:spawn-bubble` CustomEvent, App-level popover positioning pattern from `SelectionMenu`).

- **Auto-decorated terms.** `src/lib/glossary.ts` walks rendered HTML via `TreeWalker` over text nodes and wraps every occurrence of any glossary term/alias in `<span class="glossary-term" data-term="...">`. Skips `<a>`, `<code>`, `<sup>`, `<pre>`, `<script>`, `<style>`, `<button>`, `<input>`, `<textarea>`, `<select>`, `<kbd>`, and any element carrying `.ref-marker` or `.glossary-term` so the decorator never walks into citation superscripts or already-decorated content. ### What's working end-to-end

**Home screen** — Mondrian-style tile grid hung "in space" with three-layer drop shadows + perspective tilt + radial-glow background. Tiles render miniature workspace previews from each workspace's persisted BSP layout (or JSON template if not yet entered), keyed by primitive type colors. Title beneath each painting; tile aspect 3:2 matches the workspace grid 12×8.

**Workspace transitions (fly-up / fly-back)** — Tap a tile → painting flies up from its rect to fullscreen via Web Animations API (480ms cubic-bezier). Bubbles crossfade from "tile mode" (full color block, content hidden) to "workspace mode" (5px top stripe + content) via the bubble `::before` pseudo-element animating height 100% → 5px. Workspace canvas color crossfades `--bg → #0f0f0f`. FAB fades in late (240ms delay). Reverse on dismiss. HomeScreen stays mounted behind WorkspaceShell so there's no jolt at unmount.

**BSP soap-bubble layout engine** — Workspace is a binary space partition. Sub-cell precision splitAt for continuous deformation. Splitter handles between adjacent bubbles; corner handles where two splitters meet. Min-size cascade with aggressive borderization (1×1 minimum; container queries hide content at small sizes). Drag handles use Pointer Events with `setPointerCapture`, touch-capable.

**Bubble lifecycle** — Long-press to lift (slot collapses, ghost follows finger). Drop modes:
- On any bubble's body: pointer-aware splitLeafInsert with alignment-snap to nearby splitter lines (1.5-cell threshold).
- On a chat bubble: relationship menu modal — Read deeply / Scan + summarize / Held only / Editable. Source bubble is auto-named (`{TypeLabel} N`) and filed if unnamed; the mini-bubble in the brain reflects the new name.
- On a placeholder bubble: replaceLeaf — placeholder is consumed, dropped bubble takes the slot exactly.
- On a screen-edge segment: split the adjacent bubble at that edge (segments are per-bubble that touches the edge in the pointer's perpendicular position).
- On the bottom-right FAB during lift: snapshot the bubble to the per-workspace filesystem, then remove from registry. Summon back from the vault later.
- Off any bubble: snap back via originalRoot.

**Double-tap a bubble → maximize.** Walks ancestor splits, pushes each splitAt to its constraint-bounded extreme. Other bubbles compress to mins. Double-tap again restores. Different bubble while one is maximized: restore first, then maximize new from original layout.

**Chat (llm-chat primitive)** — Fully controlled (messages live in `instance.props.messages`, no local state). Real Anthropic Sonnet 4.6 replies via `/api/chat`. Loading dots while in flight; AbortController cancels on a new send. Brain bubble shows context as a status bar (no chips); hover for floating row, wrench opens task-manager rows with sortable columns. Markdown rendering on assistant/system/user messages.

**Vault** — Tap a placeholder → modal with 8 type tiles at top *and* three file sections below (This workspace / Other workspaces / Global). Pick a type → placeholder becomes a fresh bubble of that type. Pick a file → placeholder rehydrates from the file's saved instance. ✏️ inline rename next to any file row.

**Filesystem** — `src/data/filesystem.ts`. Id-keyed `Map<string, MeridianFile>` persisted to localStorage. Each file holds a serialized `BubbleInstance` plus metadata (name, type, scope, workspaceId, timestamps). Files survive bubble dismissal — that's the dismiss-and-summon-back demo flow. Two trainer markdowns are seeded on first boot.

**Multi-function FAB** (bottom-right): tap = summon placeholder; long-press = expand menu (numbered save-state grid in 2-col rows with smooth vertical scroll, plus + / ← / ⟲ actions); during lift = trash target with warn pulse on hover; while expanded the FAB shows × and tap closes.

**Workspace ⟲ reset** — Resets *positions only* of JSON-template bubbles. Preserves chat history, brain attachments, all instance content. Drops summoned non-template bubbles (placeholders, vault picks).

**Chat-internal compact / clear** — `compact` replaces messages with a single ⤓-prefixed summary system message; `clear` replaces with greeting (or empty). Both leave brain mini-bubbles intact.

**Save-state slots** — Per-workspace numbered grid (2 cols, 3 visible rows, scroll for more). Tap empty slot → snapshot registry+root via JSON clone. Tap filled → restore. Right-click filled → delete.

**Persistence** — `localStorage` hydrates `persistentWorkspaceStates` and `savedLayouts` on module load; writes through helper functions (`setWorkspaceState`, `deleteWorkspaceState`, `setSavedLayouts`) on every change. Hard refresh restores everything.

**iOS specifics** — `visualViewport` listener writes height to `--vh` so containers shrink with the keyboard. `viewport` meta `user-scalable=no, maximum-scale=1.0, viewport-fit=cover` disables native zoom. `touch-action: none` on html/body with `pan-y` re-enabled on scrollable children. iOS long-press text selection suppressed via `-webkit-touch-callout: none` + `user-select: none`.

## Architecture

### 6-level hierarchy

0. **Launcher** — top-level "meridian" screen with iOS-style app icons. Cold boot lands here. Two apps today: **Mondrian GUI** (the rest of this hierarchy) and **Mentorship Tracker** (a parallel React-style SPA, full-bleed, no BSP). Selection persists across refresh. Future Scott-artifact apps that don't fit the bubble metaphor land here as additional icons.
1. **Home screen** — iPhone-style grid of workspace tiles (paintings) on a perspective-tilted plane. Reachable from the launcher's Mondrian GUI icon.
2. **Workspace** — full-screen arrangement of bubbles. State persists across switches and refresh.
3. **Cell** — *deprecated for trainer; legacy code retained for future workspaces.* Originally LLM-chat as nucleus + organelles attached. Trainer dropped this in favor of peer bubbles after the user's feedback that chat should be its own bubble.
4. **Bubble (primitive)** — typed atomic UI unit. Resize/snap/cluster/attach via BSP. ~13 primitive types implemented.
5. **Mini-bubble** — content inside the brain bubble inside the chat, representing what the LLM has in context.

### Bubble vs SPA — when an app gets its own launcher icon

The locked rule from 2026-05-03: **bubble interface stays for clinical modules; full-bleed React-style SPAs are the right shape for dense roster / oversight / report tools that don't benefit from BSP tiling**. The Mentorship Tracker is the first SPA. Future Scott Freiberg artifacts that arrive as "this should be its own thing" get launcher icons; artifacts that extend an existing module get ported into bubbles (the two prior mentorship artifacts were ported as the Mentorship workspace bubbles, see `~/Downloads/remixed-d65093b9.tsx` + `remixed-ae62df37.tsx`). Decision goes through the user — don't unilaterally switch a TSX from bubble-port to SPA-port.

### Tangible bubbles invariant

Bubbles have **persistent identity** — the chat in Trainer is *that exact* chat (same history, same brain) when you return. Workspaces don't morph bubbles into other bubbles; transitions go *through home* (workspace shrinks to its tile, a different tile expands).

### Mondrian aesthetic

- Home tiles: black canvas, primary-color blocks (red / blue / yellow / off-white) with 1px black borders combining into 2px gridlines.
- Workspace bubbles: glass surface + 5px top stripe in the same `--type-color`.
- Single source of truth: `t-<type>` CSS classes set `--type-color`. Adding a primitive = one line in glass.css.

### Tech stack

- **Vite + Preact + TypeScript + `@preact/signals`** (decision in commit `8aa5b8e`; chosen over vanilla single-file because the resize/snap/morph mechanics + 20+ primitives needed types and HMR).
- **Cloudflare Pages** (static SPA). Pages Functions for any future backend (real LLM, integrations).
- **No backend yet** — chat is fully scripted; everything in localStorage.

### Data model (TS interfaces, in `src/types.ts`)

`WorkspaceConfig` declares cells + standalones + layoutHints (12×8 grid + per-id placements) + scripted hooks + seed sources. `BubbleInstance` carries id, type, title, props (free shape), resize states, optional attach to a cell, and an optional `fileId` linking to the filesystem. `CellConfig` has nucleus + brain + organelles (inline). `BSPRoot` wraps a recursive `BSPNode` (leaf or split). `MiniBubble` has optional `relationship: 'deep' | 'summary' | 'held' | 'edit'` (`reference` was renamed to `held`; old persisted state normalizes at read). `MeridianFile` (in `data/filesystem.ts`) holds a serialized `BubbleInstance` plus name / type / scope / workspaceId / timestamps.

### Persistence model

Two module-level Maps in `shell/workspaceState.ts`:
- `persistentWorkspaceStates: Map<workspaceId, { registry, root }>` — live state per workspace
- `savedLayouts: Map<workspaceId, SavedLayout[]>` — named save slots

Both hydrate from localStorage on module load; helpers (`setWorkspaceState`, `deleteWorkspaceState`, `setSavedLayouts`) write through to localStorage on every mutation. JSON-clone for snapshot isolation.

## Locked design decisions

- **Top-level launcher above the Mondrian GUI.** Cold boot shows iOS-style app icons. Apps that don't fit the bubble metaphor get launcher icons (Mentorship Tracker is the first SPA). Don't unilaterally migrate a TSX between bubble-port and SPA-port — go through the user.
- **Scott's TSX artifacts ship byte-identical with `// @ts-nocheck`.** When porting an SPA artifact, copy verbatim into `src/apps/<name>/`, prepend `// @ts-nocheck`, and tune UX from the host via the wrapper shell + CSS overrides on inline-style attributes. **Critical:** Preact serializes inline hex colors as `rgb(…)` in the rendered `style` attribute, so `[style*="0f1b2d"]` won't match the topbar — use `[style*="rgb(15, 27, 45)"]` (with the comma+space). When in doubt, run a headless probe to verify CSS is matching before deploying.
- **Tangible bubbles, no morphing.** Workspace transitions go through home. Bubble identity persists.
- **Mondrian for tiles, glass-with-stripe for workspace bubbles.** One `--type-color` per primitive type drives both.
- **BSP layout, not free-floating.** Workspaces are tiled; "moving" a bubble means restructuring the tile.
- **Workspace ⟲ is layout-only.** Chat has its own compact/clear; workspace ⟲ does not touch chat content.
- **Single visual treatment for v1**, themable later. No theme switcher in v1.
- **No enterprise integrations in this build.** Real LLM is fair game (no PHI), but real Epic / M365 / OpenEvidence stays in the on-prem future.
- **Mode-aware workspace layouts (clinical-modules).** The clinical-modules workspace toggles between gallery and module modes via a focus signal; layouts are tables in `BspWorkspace.tsx`. Static placement: ids in the active layout table are placed; `notes` is in every table so it follows the user. Spawned bubbles (any registry id containing `-spawned-`, the convention used by `spawnAdjacentBubble`) get follow-along treatment in `buildClinicalModulesBSP` — appended into the largest leaf after the static layout. PREVENT auto-shows for the lipid module via `MODULE_LAYOUT_WITH_PREVENT`. Chat and OE no longer appear in any static layout — they exist only as user-spawned instances from the tools cards. Other workspaces use the legacy single-layout-per-workspace path.
- **Module data is the source of truth, bubbles are pure renderers.** All module content lives in JSON (`src/data/seed/clinical-modules.json` for seeded; `userModulesSignal` for imports). Bubbles read the JSON via seed resolver and `userModulesSignal.value`; they never own state that isn't in JSON. Edit JSON, refresh, bubbles re-render. This invariant is what makes round-trip via DOCX (and any future format) cleanly possible.
- **DOCX is the round-trip format.** Word is the most familiar editor for clinical leadership. The DOCX export is structured to match the upload parser exactly so a user can export → edit in Word → upload → see in bubbles. PPTX is one-way (presentations don't round-trip). Markdown round-trip and in-app authoring are both possible future paths but deferred.
- **meridian-os is the single source of truth for evidence-rewritten modules.** Vanilla's `~/GitHub_Repos/meridian-server/modules/*.json` files are the historical seed. Once a module is rewritten through the OE-verification → JSON-rewrite pipeline (e.g., `adhd` at v1.1.0, 2026-05-03), the meridian-os entry diverges from vanilla and meridian-os is canonical. Do not propagate rewrites back to the frozen sibling. The `schema_version` field on each module entry is the marker — anything ≥1.1.0 carries a `references[]` array and inline `[ref:X]` markers; 1.0.0 entries are still byte-identical to vanilla.
- **Evidence citations live as `[ref:X]` markers inline + a top-level `references[]` array.** Each rewritten module entry carries `references: [{ ref_id, citation, url }]`. Inline prose carries plain-text `[ref:X]` markers in `answer_html`, `context_strip.text`, and `footer_note`. Phase 3 wires `expandRefMarkers` in the FAQ + print views to render markers as superscripts; the regex `\[ref:[a-z0-9-]+\]` is also stripped from `htmlToPlain` in the DOCX/PPTX export paths so markers don't leak into Word/PowerPoint plain text. Round-trip via DOCX preserves markers.
- **Floating back chevrons stack outer-scope-on-top.** The two iOS-glass pills (`‹ Mondrian` always at `top: 16px`, `‹ modules` below at `top: 60px` when relevant) sit at the App level in `main.tsx`, decoupled from any bubble's chrome. The order is breadcrumb-shaped: most-distant ancestor on top, most-recent below, so the user reads top-down to pick the level they want. When adding future scoped back affordances (e.g., a sub-page within a workspace), follow the same outer-scope-on-top stacking and re-anchor `top` so positions stay stable across mount/unmount. Both share the same dark-glass material (`backdrop-filter: blur(20px) saturate(140%)`) and `@media print` hide-list entry.
- **Tool bubbles spawn primitives via `onSpawnBubble` extraProp, not a generic emit dispatcher.** A "tool" bubble (e.g., clinical-tools) lists actions as cards; clicking a card calls `onSpawnBubble({ type, title, props? })`, which BspWorkspace routes to `spawnAdjacentBubble`. The new bubble splits the tool bubble in half and lands to its right with a unique id (`${type}-spawned-N`). Mirrors the per-primitive callback pattern already used by clinical-module-checklist's `onRequestSiblingFocus` — when a future bubble needs the workspace shell to do something, prefer adding a typed callback to the per-primitive `extraProps` switch in `BspWorkspace.tsx` over inventing a generic event channel. Spawned ids are not in the static layout tables for clinical-modules, so they disappear visually on mode switch but persist in the registry.
- **App-level components spawn via the `meridian:spawn-bubble` CustomEvent, not extraProps.** When the spawn trigger lives outside any workspace bubble (e.g. the `SelectionMenu` mounted at App level, future glossary popovers, future cite-block popovers), use `window.dispatchEvent(new CustomEvent('meridian:spawn-bubble', { detail: { workspaceId?, spec: { type, title, props?, nearBubbleId? } } }))`. `BspWorkspace` listens for this event and forwards to `spawnAdjacentBubble` only when `workspaceId` matches the active workspace (or is omitted). This is the ONLY cross-cutting bubble action so far — don't generalize to a generic dispatcher for other actions until a second cross-cutting case appears. In-bubble actions still use the typed extraProps pattern.
- **Bubble lift only triggers from the chrome handle (or `.placeholder` whole surface).** `onBubblePointerDown` in `BspWorkspace.tsx` early-returns unless `e.target.closest('.bubble__chrome, .placeholder')` matches. Pressing inside the bubble body falls through to text selection / button clicks — restoring native browser behavior in reading surfaces. The chrome row gets `cursor: grab` + a faint top-grip indicator. Trainer's drop-dossier-on-chat flow now requires lifting from the chrome row. If a future bubble type needs whole-surface lift like `.placeholder`, add it to the lift-region selector — don't go back to whole-bubble lift.
- **Text selection is opt-in by default in `.bubble__body`.** The global `body { user-select: none; -webkit-touch-callout: none }` in `reset.css` stays. `.bubble__body` and its descendants opt back in via CSS in `glass.css`; interactive elements (`button`, `input`, `select`, `textarea`, `[role="button"]`) inside the body opt back out so they don't render with a text cursor. The iOS callout suppression (`-webkit-touch-callout: none`) also stays globally because we replace the iOS callout with the App-level `SelectionMenu`. The legacy `.allow-select` opt-in class is still honored but unused in any new bubble — bubbles that want selectable text should use `.bubble__body`.
- **Selection actions live in a single App-level menu (`SelectionMenu`), not inline icons per item.** The earlier meridian-server pattern injected feedback / OE icons next to every checklist row, FAQ question, and green-zone sentence — visually noisy on dense modules. The new pattern: select text → `selectionchange` (debounced) → dark-glass floating menu above the rect with Copy / Select all / Cite / OE / Feedback. Cite and OE are gated on having an active clinical module focused (other workspaces still get a context-less menu with Copy / Select all / Feedback). Inline icons can return for non-text triggers later (e.g., a "cite this whole row" icon on a checklist row), but text-driven actions go through this menu.
- **Per-bubble font-scale: `--font-scale` CSS variable + `zoom` on `.bubble__body`.** A 0.85–1.4 multiplier per bubble id lives in localStorage (`meridian-os.bubbleFontScale.v1`); `BspWorkspace` writes it as `--font-scale` on each bsp-leaf div; `glass.css` consumes it via `.bubble__body { zoom: var(--font-scale, 1) }`. Scales every inline px font-size in the body proportionally without touching individual styles. Chrome stays at 1.0 so controls remain clickable. Persistence is independent of `instance.props` so workspace ⟲ (layout-only) doesn't reset reading preferences. `zoom` is non-standard but supported in all modern browsers (Firefox 126+, May 2024).
- **`data-bubble-id` on every BSP leaf is the canonical bubble-from-DOM lookup.** When a component (App-level menu, popover, decorator) needs to know which bubble owns a DOM node, walk `closest('[data-bubble-id]').dataset.bubbleId`. Don't grep class names for `bsp-leaf` or rely on parent-walk shortcuts.
- **Feedback is mailto-only in v1.** No server, no localStorage queue. `feedbackMailto.ts` is a pure URL builder; `FeedbackModal` mounts at App level and constructs `mailto:nschmuckler@crystalrunhealthcare.com?subject=[Meridian / {Module}] {item}&body=…` via `window.location.href`. The user's mail client picks up the draft. If feedback ever needs server-side persistence, add a Pages Function endpoint as an alternative `send` path — don't replace the mailto path, since clinical leadership recognizes the native mail draft as an explicit "send" gesture.
- **Glossary decoration is DOM-walk, every-occurrence, case-sensitive.** `decorateGlossaryHtml` / `decorateGlossaryText` use `TreeWalker` over text nodes and skip ancestors in `<a>` / `<code>` / `<sup>` / `<pre>` / `<script>` / `<style>` / `<button>` / `<input>` / `<textarea>` / `<select>` / `<kbd>` / `.ref-marker` / `.glossary-term`. Combined regex over term + alias strings, sorted longest-first so `ADHD-RS` wins over `ADHD`. Case-sensitive — `OR` (Odds Ratio) doesn't match the lowercase English `or`; `pdmp` inside a URL doesn't match `PDMP`. Word-boundary anchored; hyphenated terms work because the boundary sits at the word-char ends, not at internal punctuation. **Decorate every occurrence, not first-mention** — user found the dotted underline subtle enough that repeat decoration reads as consistent vocabulary. Order in FAQ: `decorateGlossaryHtml(expandRefMarkers(qa.answer_html, module, numberer), glossary)` — refs first (so superscripts get `.ref-marker` class), then glossary (skips into them). Reversing the order would break citation rendering.
- **Glossary entries: global by default, per-module override.** `src/data/seed/glossary.json` is the single global source. `ModuleData.glossary?: GlossaryEntry[]` is the per-module override hook (currently empty for all 7 modules); `getMergedGlossary(module, global)` puts module entries first and filters duplicates from global by exact term match. Add per-module entries when the global definition isn't precise enough for a specific module's context, not as the default. Aliases on a single entry are the right way to handle case-only or punctuation variants (`PMP`, `aHR`, `aOR`, `VA/DoD`); they don't need their own entries.
- **Popover positioning pattern is shared across `SelectionMenu` + `GlossaryPopover` + `CiteBlockPopover` (and future Track-4 catalog popovers).** Capture trigger position via `getBoundingClientRect`; place fixed-positioned overlay above by default; flip below if the rect is too close to the top; clamp x to viewport. Dark-glass material (`backdrop-filter: blur(14px) saturate(140%)` + `rgba(28, 28, 30, 0.9..0.94)`) matches the floating chevrons + selection menu. Dismiss on Esc, scroll, outside click. When future popovers land (smartphrase token expander, contract clause picker, etc.), reuse this shape rather than inventing a fourth positioning module.
- **Glossary decoration only on FAQ + checklist.** Notes (markdown) and trainer bubbles aren't decorated; they're user scratch / training UI, not module reference content. PrintView / DOCX / PPTX exports never carry decoration (no popovers on export surfaces). If a future surface should be decorated, wire the decorator at its render site — don't try to push decoration into the source data.
- **Citation extractor walks rendered DOM, not source HTML.** `extractCitations(range, module)` uses `range.cloneContents()` and queries `[data-ref]` anchors on the cloned fragment — the rendered DOM (post-`expandRefMarkers`) is the source of truth for what the user sees, not the underlying `answer_html` source string. This is why Cite only meaningfully fires inside surfaces that render `<sup class="ref-marker">` (FAQ today; checklist strips markers by design). Trying to back-derive citations from a source-HTML lookup keyed off selection offsets would be brittle when the DOM diverges from source (e.g., after glossary decoration wraps text in `<span class="glossary-term">`).
- **Citations never auto-generate.** Empty selection → explicit "No supporting citations identified — extend the selection to include a cited claim." message in `CiteBlockPopover`. The Decision text + an empty Supported-by block is the right output; the popover never invents citations from "nearby" or "module default" refs. This matches `expandRefMarkers`' missing-ref policy (visible `[ref:X]` placeholder for undeclared refs rather than silent drops) — citations are surfaced only when they're already in the rendered DOM.
- **Cite is gated on having an active module focused.** The `Cite` button is disabled (same gate as `OE`) when `activeModule === null` — i.e., outside the clinical-modules workspace, or in clinical-modules' gallery mode where no module is in focus. Without a module, there's no `references[]` to look up `[ref:X]` markers against, so the popover would have nothing useful to render. Other workspaces still get a context-less SelectionMenu with Copy / Select all / Feedback (no Cite, no OE).
- **Calculator catalog is registry-driven; calculator bubbles share `CalcShell` chrome.** `src/bubbles/_calculators/registry.ts` is the single source of truth for the calculator catalog (clinical-tools reads it; future per-module manifests will too). Each calculator lives at `src/bubbles/_calculators/{id}/index.tsx` and uses the shared `CalcShell` / `ScaleRow` / `ResultBanner` / `VerifyFooter` building blocks so chrome + footer + result-band styling stay identical across the family — adding a sixth or seventh calculator is one new directory + one registry entry. Per-calculator clinical decision rules (PHQ-9 item-9 alert, AUDIT-C ≥6 promotion, COWS ≥13 induction-threshold callout) live in the result-banner notes / tier-detail strings, not in the registry. Don't try to push them into shared.tsx — they're instrument-specific.
- **`recommended_calculators` is a sort hook, not a filter.** When a module declares `recommended_calculators?: string[]`, the matching cards float to the top of the clinical-tools calculator list with a "Recommended" badge — but every other calculator in the registry stays visible underneath. Providers can still spawn any calculator regardless of module focus; the field is a hint about relevance, not a gate. Recommend sparingly (2–4 per module) — long lists defeat the purpose of the hint. CIWA-Ar omitted from benzos is intentional: alcohol-specific instrument, would mislead.
- **Consult catalog is per-module (not a global registry like calculators).** `consults[]` lives on `ModuleData` because consult paths are content-coupled to their module's clinical voice — the ADHD `addiction-psychiatry` path knows about ASAM/AAAP 2024 framing, the benzos `geriatric-psychiatry` path knows about Bundle 8 DD1's cognitive-reversibility reframe. Calculators and glossary terms are generic; consult paths are not. If a future module wants to *reference* another module's path (e.g., the benzos module mentions "see opiates module's pain-medicine consult path"), add a `consult_ref?: { module_id: string; consult_id: string }` to the schema and resolve at render time — don't move `consults[]` to a global registry.
- **Consult walker edges include random-access by node_id.** `if_yes` / `if_no` accept `'continue' | 'recommend' | 'block' | <node_id>`. The `node_id` form is for branching that would otherwise need duplication — used by ADHD's general-psychiatry path which jumps to `addiction-psychiatry` on SUD-yes rather than re-asking the same question inside its own tree. Don't overuse it; sequential `continue` is the default for a reason. If a node references an unknown id, the walker falls through to `recommend` (visible-fallback policy, mirrors `expandRefMarkers` for missing ref ids).
- **Consult-link click goes straight to spawn, no popover.** Different from `GlossaryPopover` (which renders a tooltip first). Rationale: the consult-builder bubble *is* the popover for this affordance — the content is too long to surface in a tooltip, and the auto-spawn means there's usually already a builder on screen. If a future popover-first variant is needed (e.g., a "preview the output template" hover state), add it as a separate component without changing `ConsultLinkHandler`'s spawn-on-click behavior.
- **Auto-spawn is one-shot per module id.** `meridian-os.consultBuilderShown.{moduleId}` localStorage map gates `ConsultAutoSpawn`. Re-entering a module after dismissing the builder does NOT re-spawn. Manual re-spawn is the user's responsibility via the clinical-tools Consults card. Workspace ⟲ doesn't reset the shown map (it's per-module reading preference, not workspace layout). To demo the first-entry experience, clear the key manually.
- **Decoration order in FAQ: refs → glossary → consults.** `decorateConsultMentionsHtml(decorateGlossaryHtml(expandRefMarkers(html, ...), glossary), consults)`. Each layer's regex sees the previous layer's spans as plain text but skips into them via `SKIP_CLASSES`. Reversing the order would break: putting consult before glossary lets `nephrology` inside `nephrology consult` get glossary-decorated first, splitting the consult-link match across multiple text nodes. The order matches the print-page reading order (refs are anchored, glossary is vocabulary, consults are actions) and is the same order future Track-4 decorators (smartphrase, contract) should follow if they don't depend on each other.
